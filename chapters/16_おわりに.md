# おわりに

## 本書で作ったもの

本書を通じて、ゼロから図書館貸出システムを構築しました。

まず開発環境を整え（第 I 部）、Django と Next.js を「はじめてつなぐ」体験をしました。次に（第 II 部）データベース設計・REST API・認証・貸出管理機能と、実際のWebシステムに必要な構成要素を1つずつ積み上げました。最後に（第 III 部）テストを書き、CI で自動化し、本番公開の考え方を学びました。

完成したシステムが持つ機能を振り返ります。

|------|------------|
| 本の一覧・詳細表示 | Chapter 9 |
| 本の登録・編集・削除 | Chapter 9 |
| ユーザー認証（JWT） | Chapter 10 |
| 貸出・返却 | Chapter 11 |
| 自動テスト | Chapter 12 |
| CI（自動テスト実行） | Chapter 13 |

## 学んだ技術の全体像

本書で触れた技術を、「なぜ使うか」の観点で整理します。

**バックエンド（Django）**：データを正しく管理するための層。モデルでデータ構造を定義し、シリアライザーで入力を検証し、ビューセットで API を公開します。認証やビジネスロジックの実施はここに集中させます。

**フロントエンド（Next.js）**：ユーザーが操作する画面を作る層。API から受け取ったデータを表示し、フォームで入力を受け取り、ページ遷移を管理します。認証状態は Context で管理し、どのコンポーネントからでも参照できます。

**テストと CI**：「変えても安心」という状態を維持する仕組みです。テストがあれば変更の影響を自動確認でき、CI があればチームで並行して開発していても品質を保てます。

## 次に学ぶこと

本書のシステムは、実際のサービスに必要な要素をひと通り含んでいます。次のステップとしていくつかの方向を紹介します。

**機能の拡張**：ページネーション（大量データを分割表示）、検索・フィルタリング、ファイルアップロード（書影画像）、メール送付（返却期限通知）など、要件に合わせて機能を追加できます。

**テストの充実**：本書では代表的なテストのみ書きました。カバレッジ計測（`coverage.py`）を導入してテストの網羅率を確認したり、E2E テスト（Playwright）でブラウザ操作全体を自動化したりすることで、さらに安心して変更できるようになります。

**デプロイと運用**：Chapter 14 で紹介した PaaS への実際のデプロイに挑戦すると、「インターネットで公開されている自分のサービス」という体験ができます。ログ監視・エラー通知（Sentry など）・パフォーマンス計測も、運用の重要なテーマです。

**チーム開発**：複数人でコードを書くと、コードレビューの方法・コーディング規約（flake8, ESLint）・型チェック（mypy, TypeScript の strict モード）・ドキュメントの整備が重要になります。

## 最後に

プログラミングを「動く」から「使われる」レベルにするには、本書で扱った要素—データモデル・API 設計・認証・テスト・デプロイ—が必要になります。

1つの実際に動くシステムを最初から最後まで作ることは、個別の技術を学ぶより多くのことを教えてくれます。「どこで何をしているか」という全体像と、「なぜそう設計するか」という判断基準は、次のシステムを作るときの土台になります。

本書が、あなたのエンジニアとしての出発点になれば幸いです。
