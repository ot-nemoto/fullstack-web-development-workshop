# Chapter 8：フロントエンドとバックエンドの接続

Chapter 8 から `frontend/` と `backend/` の両方を触ります。

この章では、Chapter 7 でモックデータを使って作った画面を、実際のAPIデータに切り替えます。環境変数の管理、CORSの設定、非同期処理、ローディング・エラー処理という4つのテーマを扱います。

## 8-1 環境変数の管理

### 環境変数とは何か・なぜ必要か

**環境変数**はコードの外で管理する設定値です。APIのURLのように「開発環境と本番環境で値が変わるもの」や「パスワードのように外部に漏らしたくないもの」を管理するのに使います。

コードに直接書いてしまうと、本番デプロイのたびに書き換えが必要になり、誤ってGitHubに秘密情報を公開してしまうリスクもあります。

### 🛠️ `.env.local` を作成する

`frontend/` ディレクトリに `.env.local` ファイルを新規作成します。

```bash
# frontend/.env.local
NEXT_PUBLIC_API_URL=http://localhost:8000
```

> `.env.local` はGitにコミットしません。プロジェクトルートの `.gitignore` に `.env.local` を追加して、意図せず公開されることを防ぎます。

### 🛠️ APIのURLを環境変数で管理する

Next.js では `NEXT_PUBLIC_` で始まる環境変数はフロントエンドのコードから読み取れます（ブラウザに公開される変数）。

`frontend/src/lib/api.ts` を新規作成します。APIの呼び出しをまとめる場所です。

```typescript
const API_URL = process.env.NEXT_PUBLIC_API_URL  // 環境変数を読み込む

export async function getBooks() {
    const res = await fetch(`${API_URL}/api/books/`)
    if (!res.ok) {  // ok は HTTPステータスが 200〜299 のとき true になる
        throw new Error('本の一覧取得に失敗しました')  // throwはエラーを発生させる
    }
    return res.json()
}

export async function getBook(id: number) {
    const res = await fetch(`${API_URL}/api/books/${id}/`)
    if (!res.ok) {
        throw new Error('本の取得に失敗しました')
    }
    return res.json()
}
```

## 8-2 CORSの理解と解決

### CORSとは何か・なぜ必要か

**CORS**（Cross-Origin Resource Sharing）は、異なるオリジン（ドメイン・ポート）間のリクエストを制御するブラウザのセキュリティ機能です。

> **「オリジン」とは**：`スキーム（http/https）＋ ドメイン ＋ ポート番号` の組み合わせです。`http://localhost:3000` と `http://localhost:8000` はポートが違うため、**別のオリジン**と見なされます。

`localhost:3000`（Next.js）から `localhost:8000`（Django）へのリクエストは「オリジンが違う」と判断され、ブラウザがデフォルトでブロックします。

```
Next.js (localhost:3000) → Django (localhost:8000)
                           ↑ ポートが違う = 異なるオリジン
                           → ブラウザがブロック（CORS エラー）
```

たとえるなら、3000番のお店が「8000番の隣のお店の商品を、許可なしに取りに行こうとしている」状態です。ブラウザは「そのサーバーが本当に許可しているのか？」を確認してから通します。

> **なぜ同じPCなのにブロックされるのか**：CORSはサーバー側の意図しないリクエストを防ぐ仕組みです。悪意のあるサイトが別のサービスのAPIを勝手に呼び出す攻撃への対策として機能します。ポートが違えば「別のサービス」と判断されます。

ブラウザで JavaScript から直接APIを呼び出すと、次のような CORS エラーが発生します。

```
Access to fetch at 'http://localhost:8000/api/books/' from origin 'http://localhost:3000'
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present...
```

> **Server Component ではCORSが起きない**：Chapter 3 で確認した通り、Next.js の Server Component の `fetch` はサーバー側で実行されるため、ブラウザのCORSポリシーが適用されません。CORSエラーが発生するのは、`'use client'` コンポーネントの中で `fetch` を呼び出すときです。

DjangoにCORSを許可する設定を追加することで、フロントエンドからのリクエストを受け付けられるようになります。

### 🛠️ `django-cors-headers` をインストールして設定する

DjangoにCORSの許可設定を追加します。

```bash
pip install django-cors-headers
echo "django-cors-headers" >> requirements.txt
```

`backend/config/settings.py` を編集します。

```python
INSTALLED_APPS = [
    ...
    'corsheaders',  # 追加する
    'rest_framework',
    'library',
]

MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'corsheaders.middleware.CorsMiddleware',  # 追加する（できるだけ上に置く）
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    ...
]

# 許可するオリジンのリスト
CORS_ALLOWED_ORIGINS = [
    'http://localhost:3000',
]
```

Djangoを再起動して再度ブラウザでアクセスすると、今度はデータが表示されます。

## 8-3 非同期処理とfetch

### 同期処理と非同期処理の違い

**同期処理**は処理が終わるまで次の行に進みません。**非同期処理**は時間のかかる処理（APIリクエスト等）を待つ間、他の処理を続けられます。

たとえるなら、カフェでコーヒーを注文するときのようなものです。

- **同期処理**：カウンターで注文して、コーヒーができるまでその場に立ったまま待つ。後ろに並んでいる人は誰も進めない
- **非同期処理**：注文してから席に座って本を読む。コーヒーができたら「お待たせしました」と持ってきてもらう

ブラウザも同じで、APIリクエストを同期処理で書くと「データが返ってくるまでページ全体が固まる」という状況になります。非同期処理にすることで、データ待ちの間も他の処理（画面の描画など）を続けられます。

### 🛠️ async / await でAPIを呼ぶ

`async/await` は非同期処理を同期処理のように読みやすく書ける構文です。

```typescript
// async をつけた関数の中で await が使える
async function fetchBooks() {
    // await をつけると、Promiseの完了を待ってから次の行に進む
    const res = await fetch('http://localhost:8000/api/books/')
    const data = await res.json()
    return data
}
```

`await` は「**Promise**（将来データが入る約束）が完了するまで待つ」という指示です。`fetch()` はリクエストをサーバーに送った直後に「約束」を返します。`await` をつけることで、その約束が果たされる（データが返ってくる）まで次の行に進まないようにします。

`await` なしで書くとどうなるか：

```typescript
// 悪い例：awaitなし
const res = fetch('http://localhost:8000/api/books/')  // resはPromiseオブジェクト（まだデータがない）
const data = res.json()  // エラーになる（データがまだ届いていないため）
```

### 🛠️ レスポンスをJSONに変換する

`fetch()` が返す `Response` オブジェクトからデータを取り出すには `.json()` を呼びます。

`frontend/src/lib/api.ts` を以下のように整備します。

```typescript
import { Book, Category } from '@/types'

const API_URL = process.env.NEXT_PUBLIC_API_URL

export async function getBooks(): Promise<Book[]> {
    // Promise<Book[]> はこの関数がBook配列を返す非同期処理であることを示す型注釈
    const res = await fetch(`${API_URL}/api/books/`)
    if (!res.ok) {
        throw new Error(`APIエラー: ${res.status}`)
    }
    return res.json()
}

export async function getBook(id: number): Promise<Book> {
    const res = await fetch(`${API_URL}/api/books/${id}/`)
    if (!res.ok) {
        throw new Error(`APIエラー: ${res.status}`)
    }
    return res.json()
}

export async function getCategories(): Promise<Category[]> {
    const res = await fetch(`${API_URL}/api/categories/`)
    if (!res.ok) {
        throw new Error(`APIエラー: ${res.status}`)
    }
    return res.json()
}

export async function createBook(data: Omit<Book, 'id'>): Promise<Book> {
    // Omit<Book, 'id'> は Book型から id を除いた型（新規作成時はidがまだない）
    const res = await fetch(`${API_URL}/api/books/`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data),  // JSON.stringify はJavaScriptオブジェクトをJSON文字列に変換する
    })
    if (!res.ok) {
        throw new Error(`APIエラー: ${res.status}`)
    }
    return res.json()
}

export async function updateBook(id: number, data: Partial<Book>): Promise<Book> {
    // Partial<Book> はBookの全プロパティをオプショナル（省略可能）にした型
    const res = await fetch(`${API_URL}/api/books/${id}/`, {
        method: 'PUT',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data),
    })
    if (!res.ok) {
        throw new Error(`APIエラー: ${res.status}`)
    }
    return res.json()
}

export async function deleteBook(id: number): Promise<void> {
    const res = await fetch(`${API_URL}/api/books/${id}/`, {
        method: 'DELETE',
    })
    if (!res.ok) {
        throw new Error(`APIエラー: ${res.status}`)
    }
}
```

### 🛠️ `books/page.tsx` をAPIデータに切り替える

`api.ts` が整ったので、Chapter 7 で作った `frontend/src/app/books/page.tsx` をモックデータからAPI呼び出しに切り替えます。

```tsx
import { getBooks } from '@/lib/api'
import BookCard from '@/components/BookCard'

export const dynamic = 'force-dynamic'  // APIフェッチがあるため静的プリレンダリングを無効化する

export default async function BooksPage() {
    const books = await getBooks()
    return (
        <main className="container mx-auto p-8">
            <h1 className="text-2xl font-bold mb-6">本の一覧</h1>
            <div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4">
                {books.map((book) => (
                    <BookCard key={book.id} book={book} />
                ))}
            </div>
        </main>
    )
}
```

`mockBooks` の import がなくなり、代わりに `getBooks()` を `await` で呼び出しています。関数に `async` を追加していることに注意してください。

## 8-4 ローディング・エラー処理

APIリクエスト中のユーザー体験を改善します。データ取得中は「読み込み中」を表示し、エラー時は「失敗しました」を表示します。

### 🛠️ loading.tsx でローディング状態を表示する

`frontend/src/app/books/loading.tsx` を作成します。

```tsx
export default function Loading() {
    return (
        <main className="container mx-auto p-8">
            <p className="text-gray-500">読み込み中...</p>
        </main>
    )
}
```

`loading.tsx` を同じフォルダに置くだけで、Next.jsがデータ取得中に自動的にこのコンポーネントを表示します。

### 🛠️ error.tsx でエラー状態を表示する

`frontend/src/app/books/error.tsx` を作成します。

```tsx
'use client'  // error.tsx は Client Component でなければならない

interface ErrorProps {
    error: Error
    reset: () => void  // () => void は引数なし・戻り値なしの関数型
}

export default function Error({ error, reset }: ErrorProps) {
    return (
        <main className="container mx-auto p-8">
            <h2 className="text-red-500 font-bold">エラーが発生しました</h2>
            <p className="text-gray-600">{error.message}</p>
            <button
                onClick={reset}
                className="mt-4 px-4 py-2 bg-blue-500 text-white rounded"
            >
                再試行する
            </button>
        </main>
    )
}
```

`reset` はNext.jsが提供する「ページを再読み込みする」関数です。ボタンに渡すことで、エラー後にユーザーが自分でリトライできます。

### ユーザーへのフィードバックの重要性

ローディングとエラー処理は「動けば良い」という段階を超えて、**ユーザー体験**に直結します。

- ローディング表示がないと、画面が空白のままフリーズしているように見える
- エラーメッセージがないと、何が起きたかユーザーが判断できない
- 再試行ボタンがないと、エラー後にユーザーがどうすれば良いかわからない

小さな工夫ですが、これがあるかないかでアプリの完成度は大きく変わります。
